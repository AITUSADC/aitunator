# AITUNATOR

Ассистент по официальной информации Astana IT University для абитуриентов и студентов.

[История изменений](CHANGELOG.md) — выполненная работа по коммитам и текущие изменения.

Реализованы гибридный поиск, обработка сравнений образовательных программ и
асинхронный пайплайн генерации ответов. Генерация включает историю, проверку
достаточности контекста и отказы. Её качество на реальной LLM и задержки ещё
не измерены; подключение API и веб-интерфейса выполняется отдельно.

## Как работает поиск

```text
Вопрос
  → определение программ и темы
  → отдельный запрос по каждой программе, если их несколько
  → BM25 + BGE-M3
  → объединение результатов через RRF
  → приоритет нужных разделов
  → до 5 фрагментов для ответа
```

BM25 ищет точные слова и обозначения, BGE-M3 — близкие по смыслу фрагменты.
Оба метода используются в каждом поисковом запросе.

Если названа программа, поиск ограничивается её документами. Для сравнений
результаты отбираются по очереди из каждой программы в пределах общего top-5.
Вопросы без привязки к программе обрабатываются по всему корпусу.

Вопросы о навыках, дисциплинах и карьере получают приоритет соответствующих
разделов среди найденных кандидатов. При неизвестной теме сохраняется исходный
порядок. Обязательный нейросетевой rerank и ранний выход по confidence отключены
в выбранной поисковой схеме.

Точка входа: [`backend/app/rag/pipeline.py`](backend/app/rag/pipeline.py).
Функция `search()` возвращает найденные фрагменты, времена и подзапросы.
Асинхронная `answer()` выдаёт события для API.

## Стек

- **Python 3.12+**
- **BGE-M3 / Sentence Transformers** — эмбеддинги
- **rank-bm25 / NLTK** — лексический поиск и токенизация
- **NumPy** — точный векторный поиск в локальных экспериментах
- **Qdrant** — адаптер индексации документов

Целевая архитектура приложения: один сервис FastAPI, SQLite для истории,
Qdrant и фронтенд на Vite + React + TypeScript.

## Установка и тесты

Все команды выполняются из корня репозитория. Пример для PowerShell:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -e .
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

Базовая установка позволяет запустить тесты без моделей, базы документов и сети.
Для эмбеддингов установите дополнительные зависимости:

```powershell
.venv/Scripts/python.exe -m pip install -e ".[models]"
```

Дополнительные группы зависимостей: `qdrant` для индексации и `pdf` для
опционального PDF-парсера. Полный список — в [`pyproject.toml`](pyproject.toml).

## Данные и оценка поиска

Для экспериментов нужны локальные файлы:

| Путь | Содержимое |
|---|---|
| `data/md/` | Документы базы знаний в Markdown |
| `runtime/points_cache.jsonl` | Чанки, метаданные и векторы документов |
| `tmp/models/` | Кеш моделей |

Документы, векторы и модели **не входят в Git**. После клонирования необходимо
получить совместимый снимок базы или подготовить собственный. Набор вопросов
[`eval/golden.jsonl`](eval/golden.jsonl) включён в репозиторий; его разметка
соответствует корпусу, использованному в экспериментах.

Сравнение BM25, векторного и гибридного поиска:

```powershell
.venv/Scripts/python.exe -m eval.run --modes bm25 dense hybrid --candidates 8 --repeats 1
```

По умолчанию модели загружаются из локального кеша. Для первоначального
скачивания добавьте `--download-models`. Проверка только BM25 не требует моделей,
но использует тот же файл корпуса.

Эксперименты с представлением документов и отбором разделов:

```powershell
.venv/Scripts/python.exe -m eval.structured_compare
.venv/Scripts/python.exe -m eval.section_compare
```

Первый запуск создаёт векторы карточек и может занять заметное время на CPU.
Второй использует его готовые `cards.jsonl` и `summary.json` из
`runtime/structured-experiment/`. Отчёты содержат метрики, результаты отдельных
запросов и времена выполнения; сохраняются в `runtime/`.

### Результаты

Локальный корпус: 319 фрагментов. Набор: 139 вопросов, из них 92 с разметкой
нужных разделов. Общий лимит — 5 результатов.

| Проверка | Исходный гибрид | Гибрид с разбиением по программам и отбором разделов |
|---|---:|---:|
| Найдены все размеченные разделы | 85/92 — 92,4% | 91/92 — 98,9% |
| Найдены разделы обеих программ в сравнениях | 3/8 | 8/8 |
| Найден нужный документ для общих вопросов | 30/30 | 30/30 |

Для общих вопросов пока размечены только документы, поэтому последняя строка
не подтверждает полноту найденных фактов. Сравнения программ составлены по
шаблонам; результаты требуют проверки на независимых формулировках.
Это оценка поиска, а не правильности ответов LLM. Замеры выполнены локально,
без сетевых задержек Qdrant и генерации ответа.

Карточки с новым представлением текста не дали преимущества над исходными
векторами после добавления отбора разделов. Для выбранной схемы переэмбеддинг
документов не требуется.

## Индексация

Унаследованный индексатор находится в `backend/app/ingest/index.py`.
Для его запуска необходим доступный Qdrant и зависимости `models,qdrant`.
Параметры подключения задаются через переменные окружения `QDRANT_URL`,
`QDRANT_API_KEY`, `QDRANT_COLLECTION`; остальные настройки — в
[`backend/app/config.py`](backend/app/config.py).

Индексатор ещё требует доработки: переключение коллекций через alias и удаление
устаревших чанков при обновлении не реализованы.

## Генерация ответов

Установка: `python -m pip install -e ".[models,rag]"`.
Настройки перечислены в [`.env.rag.example`](.env.rag.example). Передайте их в
окружение процесса через ваш launcher или Compose; Python-модули не читают `.env`
автоматически. Существующий `.env` не заменяйте. Для Groq используются
`GROQ_API_KEY`, `LLM_MAIN_MODEL` (или `LLM_MODEL`) и `LLM_FAST_MODEL`.
Поддерживается также `LLM_PROVIDER=compatible` с явно заданными `LLM_BASE_URL`
и `LLM_API_KEY`. Endpoint должен поддерживать JSON mode и SSE chat completions.
Доступность выбранных моделей следует проверить в аккаунте провайдера.

Запуск из корня проекта после настройки окружения:

```text
python -m backend.app.rag.cli "Какие предметы изучают на Software Engineering?"
```

В lifespan приложения нужно вызвать `await pipeline.startup()`, затем читать
`pipeline.answer(question, history, program_code=None)` через `async for`.
При завершении — `await pipeline.shutdown()`. `pipeline.is_ready()` сообщает
готовность; ошибка startup должна приводить к недоступности режима real.
Инициализация проверяет локальный корпус и соответствие сохранённых векторов
модели на трёх образцах; без данных или модели запуск завершается ошибкой.
Никаких загрузок моделей при импорте и автоматической подмены моком нет.

История — последние 10 завершённых сообщений `{role, content}`, без текущего
вопроса. При наличии истории быстрая модель формирует самостоятельный запрос.
После поиска она проверяет достаточность фактов: при нехватке допускается
один повтор поиска, затем отказ. Основная модель получает только выбранные
фрагменты и выдаёт поток текста; нейросетевого reranker нет.

События: `status {stage}`, `token {text}`, `done {finish_reason, diagnostics}`,
`error {code, message, retryable}`, каждое также содержит `type`.
Причины завершения: `stop`, `guardrail`, `no_data`.
Источники находятся только в `diagnostics.sources`; API должен сохранять их
внутренне, не передавая diagnostics клиенту. Идентификаторы сообщений и запись
SQLite остаются ответственностью API. Ошибки модели, оборванный поток и
достижение лимита токенов не превращаются в успешный `done`.

`CancelledError` распространяется до HTTP-провайдера и закрывает ответ.
Уже запущенный CPU-поиск в `to_thread` завершится в фоне; его результат
отменённому запросу не выдаётся. Доступ к embedder сериализован внутри рабочего
потока. Модели и корпус переиспользуются между запросами.

Ограничения: runtime пока использует локальный `points_cache.jsonl`, а не Qdrant;
8 кандидатов сохранены из поискового эксперимента. Проверка фактов добавляет
LLM-вызов перед первым токеном, поэтому целевые TTFT и 20 параллельных ответов
ещё требуют измерений. Правила ПДн покрывают распространённые форматы, но не
все личные данные; выходной поток не проходит отдельную семантическую модерацию.
Проверка сохранения ПДн на стороне API по-прежнему обязательна.
